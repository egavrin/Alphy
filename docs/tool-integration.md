# Native mini-app integration

`ToolGenerationService` serves the chat and library entry points. It uses an injected `ChatProvider` and a request-specific `CloudSession`. Requests contain the current prompt and confirmed images. Refinement includes the current schema and program. Private record or capability-result artifacts omit live state, initial defaults, and UI from that request. Generation does not reuse chat history or old image references.

`ToolSpec` accepts artifact protocol 3. Earlier protocols remain stored with their data intact but cannot execute. The definition includes a bounded state schema, initial state, native UI, one JavaScript function body, and declared capabilities. Optional fields declare private collections, typed capability results, and at most four identified drawing surfaces. `ToolUiCatalog.modelGuidance()`, `ArtifactProtocol.modelGuidance()`, and `CapabilityCatalog.modelGuidance()` supply the implemented generation catalogs.

State supports scalar values and bounded lists, objects, and arrays. State has a 48 KiB limit. Source has a 32 KiB limit. Native UI has a 32 KiB limit, 256 structural nodes, depth eight, and an aggregate rendered-work limit. The complete sandbox envelope has a 64 KiB limit. Native controls include typed forms, semantic containers, row templates, charts, motion, and bounded perspective layers. The contracts reject unknown fields and invalid bindings.

Generated colors follow the Alphy light or dark color scheme. Text, styled containers, and drawing commands share six roles: `default`, `muted`, `accent`, `success`, `warning`, and `error`. The six `theme.preset` values use colors from the active scheme. A saved definition with `theme.palette` or `theme.mode` stays in the library with its data and version history. Its controls cannot run. The user can explicitly delete it.

One artifact handler receives native actions, lifecycle events, identified surface events, subscribed frames, and subscribed timers. Native frame requests follow the display clock. Generated simulations use `dt` rather than a fixed frame rate. Drawing supports bounded shapes, paths, gradients, and affine groups. The canvas uses the shell surface color. Solid fills and gradient stops accept role names, `#RRGGBB`, or `#AARRGGBB`. Use roles for scene text and frames. Drawing limits apply to the retained union across surfaces.

Frame, pointer, timer, and control evaluations use a fixed 100 ms asynchronous watchdog. Other evaluations use 500 ms. The monotonic cutoff starts before native submission and includes execution and asynchronous result completion. Both retained sessions and disposable smoke use these limits. Timeout closes the isolate and rejects its result without an event retry or a state or effect commit. These limits do not measure script CPU time or guarantee a displayed frame rate.

Generation validates a candidate before acceptance. Each disposable sandbox branch uses the ordinary transient slot. The branch closes its lease in `finally`. It does not replace the foreground retained lease. Preview and render must preserve the input state. A separate branch opens the candidate and exercises every declared surface, pointer transitions for both pointer IDs, both control directions, subscribed frames and timers, and start, pause, resume, restart, and stop events.

Each available control receives representative valid typed values. Samples include current values and bounded alternatives, the first and last selection options, and the first and last collection rows. Row templates use current stable keys. Each independent action branch starts with the disposable initial state and a new transient lease. The production action validator checks each action. The production result validators check every returned state, UI, drawing, subscription, effect request, and record request. Merged drawing also receives aggregate validation before the next smoke event.

Smoke validates requests without executing them. It has no store, capability broker, launcher, provider, scheduler, permission, or grant interface. It never creates capability or record result events. A pending effect or record request ends that action branch. The accepted preview retains its original validated state. Open, action, frame, pointer, timer, and lifecycle smoke state never becomes accepted state.

New app generation permits three repairs each for PLAN and COMPLETE. A repair patches a usable candidate or uses the stage's one full rewrite when no usable candidate exists. Generated script errors, execution timeouts, and invalid results enter that flow. The diagnostic records structural paths, step and slot numbers, and event kinds. Diagnostics exclude live values, generated IDs, and raw exception text. The repair request also includes the rejected candidate. Infrastructure failures such as a busy transient slot return directly. Cancellation preserves the prior artifact and its records, grants, and revisions.

`ArtifactCoordinator` serializes runtime transitions for an artifact and its surfaces. Revision and state tokens reject stale commands. Only frame and pointer-move publications use coalesced persistence. Native actions, result deliveries, private records, and effects retain guarded commits. Pending native work fences autonomous events. No failed native effect receives an automatic retry.

`ToolStore` retains accepted tools, revisions, drafts, collections, grants, and native result receipts. Acceptance saves the candidate and removes its draft atomically. Rejection removes only the selected draft. Refinement preserves existing field types, collection schemas, stable IDs, and saved values. Rollback creates a revision only when its schema accepts the current state.

`ToolController` exposes the workflow to Compose. Chat cards, the library, the focused app, widgets, and automations use the same artifact contracts. Generated JavaScript has no direct network, files, credentials, Android APIs, imports, or generated Kotlin. Native capability execution still requires its declared contract, grants, permissions, selections, and confirmation rules.

Smoke is a bounded deterministic sample. It does not prove arbitrary user sequences, real provider results, displayed frame rate, or hardware touch latency. Root acceptance verifies those requirements separately.
